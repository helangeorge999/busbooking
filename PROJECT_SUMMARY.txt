6. API / NETWORK LAYER
=============================================

Base URL: http://{ip}:5050/api
- Emulator: 10.0.2.2:5050
- Physical device: 192.168.1.152:5050
- Smart detection via device_info_plus

Auth Endpoints:
  - POST /api/auth/login         - User login
  - POST /api/auth/register      - User registration
  - POST /api/auth/forgot-password - Request OTP
  - POST /api/auth/reset-password  - Reset password with OTP

Bus Endpoints:
  - GET /api/buses               - All buses (admin)
  - GET /api/buses/search?from=&to=&date= - Search buses
  - GET /api/buses/{id}          - Bus details

Booking Endpoints:
  - POST /api/bookings           - Create booking
  - GET /api/bookings            - All bookings (admin)
  - GET /api/bookings/my-bookings - User's bookings
  - GET /api/bookings/bus/{busId} - Bookings for a bus
  - PATCH /api/bookings/{id}/cancel - Cancel booking

User Endpoints:
  - GET /api/user/profile?userId={id} - Get profile
  - POST /api/user/upload-photo       - Upload photo (multipart)

Admin Endpoints:
  - POST /api/admin/auth/login   - Admin login
  - GET /api/admin/stats         - Dashboard statistics

HTTP Client: Uses `http` package, 10-second timeout, custom error handling.

9. AUTHENTICATION FLOW
=============================================

Login:
  1. User enters email/password on LoginPage
  2. Toggle between "User" and "Admin" mode
  3. POST to /api/auth/login or /api/admin/auth/login
  4. On success: store token + profile in SharedPreferences, navigate to MainShell or AdminShell
  5. Offline fallback: if token exists, proceed to home with cached data

Registration:
  1. Fill form: name, email, phone, DOB, gender, password, confirm password
  2. Client-side validation (email format, password match, all fields required)
  3. POST to /api/auth/register
  4. On success: show message, auto-navigate to LoginPage after 1 second

Forgot Password:
  1. Enter email -> POST /api/auth/forgot-password
  2. Backend returns OTP (shown in dialog)
  3. Enter OTP + new password -> POST /api/auth/reset-password
  4. On success: return to LoginPage

10. SENSOR / DEVICE FEATURES
=============================================

Accelerometer (sensors_plus):
  - Measures X, Y, Z acceleration in m/s²
  - Range: +/-20 m/s²

Gyroscope (sensors_plus):
  - Measures X, Y, Z rotation in rad/s
  - Range: +/-10 rad/s

Magnetometer (sensors_plus):
  - Measures X, Y, Z magnetic field in uT
  - Compass heading via atan2(magY, magX)
  - Direction: N, NE, E, SE, S, SW, W, NW
  - Range: +/-100 uT

Light Sensor (light_sensor):
  - Measures ambient light in lux
  - Levels: Very Dark (<10), Dark (<50), Dim (<200), Normal (<1000), Bright (<10k), Very Bright
  - Auto-Brightness: <20 lux -> dark mode, >100 lux -> light mode (2-sec debounce)
  - Requires physical device (not available on emulator)

All sensors stream real-time data via StreamSubscription, cancelled on dispose.

  - Journey Details: departure time/city, arrival time/city
  - Booking Info: seats, passengers, boarding point, travel date, name, contact, email, bus type
  - Booking ID: unique identifier (BK{timestamp} or backend-provided)

Output: In-memory PDF bytes shared via system share dialog (save, print, email).
